# Execution Plan

План для исполнителя-ИИ. Работа **только по пунктам**. К следующему пункту **не переходить**, пока заказчик явно не апрувнет текущий.

Формат апрува: сообщение в чате вроде «ок», «апрув», «пункт N принят». Молчание, правки «почти то» и собственные «логически дальше» — **не апрув**.

После каждого пункта исполнитель:

1. кратко показывает, что сделано (файлы, команды, поведение);
2. пишет **стоп-критерий** и **что проверить** заказчику;
3. останавливается и ждёт апрув.

Запрещено в одном заходе закрывать два пункта, «заодно» писать следующий слой, рефакторить уже принятое без запроса.

Язык реализации: **Go**. Норматив: `CONSTRAINTS_AND_POLICY.md`. Если план и политика расходятся — остановиться и спросить заказчика, не импровизировать.

---

## Пункт 0. Подтверждение границ

**Сделать:** ничего в коде. Зафиксировать, что исполнитель прочитал оба MD и будет им следовать.

**Отдать заказчику:** список открытых допущений из политики (если остались). Если допущений нет — одна фраза «допущений нет».

**Стоп:** ждать апрув пункта 0.

---

## Пункт 1. Каркас CLI

**Сделать:**

- модуль Go в `d:\csv converter`;
- `main`: точка входа консольного приложения;
- проверка `C:\Source\db`: нет пути или не директория → сообщение в stderr, `os.Exit(1)`;
- если корень есть — пока только сообщение «корень найден» и `exit 0` (конвертации ещё нет);
- `--help` с кратким описанием.

**Не делать:** обход дерева, парсер SQL, CSV.

**Проверка заказчиком:** запуск без `C:\Source\db` падает; с существующим корнем (если появится) — exit 0.

**Стоп:** ждать апрув пункта 1.

---

## Пункт 2. Обход дерева и список SQL

**Сделать:**

- рекурсивный обход `C:\Source\db` без следования symlink;
- сбор путей `*.sql` (без учёта регистра);
- для каждого файла определить верхнюю папку (первый сегмент относительно `db`);
- SQL в корне `db` пометить отдельно (в `converted.txt` не пойдут);
- вывод в лог: сколько файлов найдено (без конвертации).

**Не делать:** чтение содержимого SQL дальше открытия для проверки доступности, запись CSV.

**Проверка:** на фикстуре с вложенными папками список путей совпадает с ожидаемым.

**Стоп:** ждать апрув пункта 2.

---

## Пункт 3. Потоковый извлекатель INSERT

**Сделать:**

- сканер `io.Reader` → последовательность INSERT;
- для каждого INSERT: имя таблицы (без схемы), список колонок, набор строк значений;
- пропуск `INSERT ... SELECT`, `INSERT ... SET`, INSERT без списка колонок, битый SQL — с записью в лог;
- не читать весь файл в память.

**Не делать:** запись CSV, `converted.txt`.

**Проверка:** юнит-тесты на фикстурах (один/много VALUES, кавычки `''`, backticks, комментарии, несколько INSERT в одном файле, большой многострочный INSERT). Тесты класть в репозиторий, не на `C:\Source\db`.

**Стоп:** ждать апрув пункта 3.

---

## Пункт 4. Запись CSV

**Сделать:**

- UTF-8 без BOM, разделитель `,`, каждая ячейка в `"..."`, внутренние `"` → `""`;
- первая строка — только имена колонок;
- `NULL` → `""`;
- путь: рядом с `.sql`;
- имя `{table}.csv`, при занятом имени `{table}(1).csv`, `(2)`, …;
- не перезаписывать существующие файлы;
- коллизии имён в одной директории сериализовать.

**Не делать:** финальный `converted.txt` (можно копить в памяти список успешных верхних папок).

**Проверка:** снимок байтов CSV (нет BOM, кавычки, заголовок без слова INSERT). Существующий файл не затирается, появляется `(1)`.

**Стоп:** ждать апрув пункта 4.

---

## Пункт 5. Склейка: файл SQL → набор CSV

**Сделать:**

- для каждого найденного `.sql` прогнать пункт 3 + 4;
- ошибка открытия/чтения файла: warn/error в лог, следующий файл;
- ошибка одного INSERT: лог, следующий INSERT;
- сводка по файлу в лог (успехи / пропуски).

**Не делать:** ещё `converted.txt` на диск, если это удобнее вынести в пункт 6 — тогда здесь только in-memory набор верхних папок с успехом.

**Проверка:** один SQL с двумя INSERT в разные таблицы → два CSV рядом; два INSERT в одну таблицу → `t.csv` и `t(1).csv`.

**Стоп:** ждать апрув пункта 5.

---

## Пункт 6. `converted.txt` и финальный код выхода

**Сделать:**

- после обработки всех файлов записать `C:\Source\db\converted.txt`;
- только верхние папки, где был ≥1 успешный CSV;
- сортировка по имени, UTF-8 без BOM, одно имя на строку;
- перезапись файла с прошлого запуска;
- если успехов не было — пустой `converted.txt`;
- итоговая сводка в stderr;
- exit 0 при существующем корне; exit 1 только по правилам политики (нет корня / корень не директория).

**Проверка:** вложенный SQL в `db\Alpha\x\y\a.sql` даёт в `converted.txt` строку `Alpha`, не `Alpha\x`. Папка без успешных INSERT отсутствует в списке.

**Стоп:** ждать апрув пункта 6.

---

## Пункт 7. Логирование и устойчивость на объёме

**Сделать:**

- пул воркеров по файлам (лимит = `GOMAXPROCS` или небольшой константный потолок);
- логи только в stderr, файл лога не создаётся;
- в лог не писать полные VALUES;
- прогресс: периодически число обработанных файлов.

**Проверка:** искусственный битый SQL не роняет процесс; второй файл после битого обрабатывается.

**Стоп:** ждать апрув пункта 7.

---

## Пункт 8. Сборка и инструкция запуска

**Сделать:**

- `go build` в бинарник с понятным именем (`sql2csv.exe`);
- короткий `README.md`: как собрать, как запустить, что будет в `C:\Source\db`, код выхода.
- не описывать политику заново — ссылка на `CONSTRAINTS_AND_POLICY.md`.

**Проверка:** заказчик собирает и запускает из консоли без IDE.

**Стоп:** ждать апрув пункта 8.

---

## Пункт 9. Скрипт установки на новое устройство

**Сделать:**

- скрипт для Windows (PowerShell: `setup.ps1`), который на чистой машине готовит запуск конвертера;
- проверить наличие Go; если нет — установить (предпочтительно `winget`, запасной путь — официальный installer / инструкция, если winget недоступен);
- перейти в каталог проекта, `go mod download`, `go build` в `sql2csv.exe`;
- если сборка уже есть и зависимости на месте — не ломать окружение, идемпотентный повторный запуск;
- ненулевой exit и понятное сообщение, если установка Go или сборка не удалась;
- в `README.md` добавить один блок: как один раз запустить `setup.ps1` на новом устройстве (политика выполнения скриптов: `Set-ExecutionPolicy` только для текущего процесса, не менять политику машины глобально).

**Не делать:** установку IDE, Git, правку `C:\Source\db`, тихую установку пакетов без вывода в консоль.

**Проверка:** на машине без заранее поставленного Go скрипт ставит toolchain, качает модули, собирает `sql2csv.exe`; повторный запуск не падает.

**Стоп:** ждать апрув пункта 9. На этом план закрыт.

---

## Правила на всём протяжении

| Нельзя | Можно |
|---|---|
| Переходить к пункту N+1 без апрува N | Уточнять вопрос, если пункт нельзя выполнить однозначно |
| Менять уже принятый пункт «тихо» | Предложить правку и ждать апрув |
| Писать код вне текущего пункта | Фикстуры и тесты **текущего** пункта |
| Ходить в `C:\Source\db` как в обязательный набор данных разработки | Локальные фикстуры в репозитории |
| Менять политику в коде без правки MD | Сначала предложить правку MD, потом ждать апрув |

Если заказчик апрувит пункт с замечанием («ок, но переименуй X») — сначала внести замечание в рамках **этого** пункта, снова показать результат, снова ждать апрув. Следующий пункт не открывать.
