## Цель

1. **Один глобальный пул** воркеров: `1 INSERT = 1 задание`; свободные воркеры забирают другие директории той же верхней папки, затем другие верхние папки. Commit в один ключ — строго по порядку «сверху вниз», не по finish-time.
2. **Нарезка CSV**: больше 1_000_000 строк данных → куски по ≤ 500_000; первый файл без суффикса, дальше `_2`, `_3`, …. То же для заранее лежавших `.csv`, которые мы не конвертировали.
3. **Удаление исходников** `.sql` / `.xlsx` / `.xls` только после полной обработки файла, и только если из него получен хотя бы один CSV.

## Пункт 0. Принятые правила (код не писать)

Это зафиксированные ответы заказчика. Новых правил сверх них не выдумывать.

### 0.1. Пул и приоритет

- `N = min(GOMAXPROCS, 16)`, не меньше 1.
- Один глобальный пул на весь корень. Воркеры перетекают: нет «слота, привязанного к верхней папке».
- Единица SQL: один найденный `INSERT ... VALUES`. Один mega-INSERT — одно задание (пачку VALUES внутри не резать).
- Приоритет очереди:
  1. INSERT / работа текущего уже открытого `.sql`;
  2. другие директории той же верхней папки;
  3. другие верхние папки.
- Сканер файла последовательный (границы statement, кавычки, комментарии). Параллелится разбор VALUES разных INSERT, не поиск границ с середины файла.
- **Commit** в ключ `(dir, table)` — очередь по `(путь .sql, offset INSERT)`. Заголовок и ширина — от самого верхнего успешного INSERT, как §5.
- Excel одной директории не стартовать, пока все SQL этой директории не закрыты.
- `converted.txt` — только когда **вся** верхняя папка досчитана (конверт + нарезка + удаления).
- Ранний PII-reject: VALUES в ячейки не парсить.

### 0.2. Нарезка

| Строк данных | Действие |
|---|---|
| ≤ 1_000_000 | не трогать |
| > 1_000_000 | `ceil(N / 500_000)` файлов, в каждом ≤ 500_000 данных |

Имена: `{stem}.csv`, `{stem}_2.csv`, `{stem}_3.csv`. Не `(n)`, не `_part`.

Заголовок (если есть) копировать в каждый кусок; в порог не входит. Чужой CSV: первая непустая строка = заголовок. Наш CSV без шапки (INSERT без колонок): все строки — данные.

Резать и наши свежие файлы (после закрытия ключа), и любые `.csv` в незавершённых папках / корне, которые лежали заранее. `converted.txt` и `.2csv-*.tmp` не резать.

Поток по строкам. Монолит не удалять, пока куски на месте. Столкновение `{stem}_2.csv` — заменить частью нарезки.

### 0.3. Удаление исходников

Разрешено заказчиком. Удалять `.sql` / `.xlsx` / `.xls` **только если** из файла в этом запуске получен ≥1 CSV.

Порядок: сначала CSV на диске → нарезка этих ключей если нужна → `os.Remove` исходника. Не править исходник на месте.

Не удалять: PII-skip, книга >5 листов, битый/неоткрытый, 0 CSV. Ошибка `Remove` — `error` в лог, обход дальше, CSV не откатывать.

### 0.4. Лог и `converted.txt`

Висящая строка раз в секунду. Верхних папок может быть несколько сразу: перечислить активные или самую давнюю.

Итог папки как сейчас, плюс: папка только с нарезанным чужим CSV считается «создан CSV» и идёт в `converted.txt`. Нет sql/excel/csv — `нет файлов`.

Не логировать каждый успешный split и каждый успешный delete.

### 0.5. Что не менять

- корни только `C:\Source\db` и `C:\Source\combo`;
- формат ячейки §6;
- склейка INSERT одного ключа в один логический файл **до** нарезки;
- PII-матчер и порог двух колонок;
- Excel: лимит 5 листов, имя `{книга}_{лист}.csv`;
- не ходить выше корня;
- не добавлять `--force` и флаг пути;
- не логировать содержимое ячеек.

**Стоп:** ждать апрув пункта 0. Если допущений нет — написать «допущений нет» и ждать. Если есть — перечислить и ждать.

## Порядок на диске в одном прогоне директории

Агент должен сохранить эту последовательность, даже когда задания идут из общего пула:

```text
cleanup .2csv-*.tmp
SQL этой dir (сканер → INSERT-jobs → ordered commit по ключам)
барьер: все SQL dir закрыты
Excel этой dir
закрыть Excel-ключи
нарезка закрытых ключей этой dir + чужие .csv этой dir
удаление исходников этой dir, у которых ≥1 CSV
когда все dir верхней папки + их нарезка/delete готовы:
  итог папки и converted.txt
```
