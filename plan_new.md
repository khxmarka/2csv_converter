## Зачем

Сейчас каждый оператор `INSERT` даёт новый файл (`orders.csv`, `orders(1).csv`, …). Нужно иначе: все успешные `INSERT` в **одну и ту же таблицу в одной директории** попадают в **один** CSV. Заголовок — только у самого верхнего успешного INSERT. У остальных INSERT список колонок в CSV не пишется, дописываются только строки данных.

## Пункт 1. Поведение склейки в `csvout` / записи

**Сделать:**

- ключ склейки: `(директория .sql, имя файла таблицы после санитайза)` — не сырое SQL-имя со схемой;
- первый успешный INSERT по ключу: создать CSV как сейчас (заголовок + строки), подобрать свободное имя `{table}.csv` / `{table}(n).csv` **один раз за запуск**;
- следующие успешные INSERT по тому же ключу в том же запуске: **не** писать строку заголовка, **не** брать новое `(n)`, дописать только строки `VALUES` в уже выбранный файл;
- чужой файл с прошлого запуска не перезаписывать: если `t.csv` уже был до этого запуска, первый INSERT этого запуска открывает `t(1).csv`, остальные INSERT в `t` в этой папке дописывают в `t(1).csv`, а не плодят `t(2).csv`;
- заголовок навсегда фиксируется по **первому успешному** INSERT ключа; списки колонок у последующих INSERT в CSV игнорируются;
- арность последующего INSERT сравнивать с **числом колонок заголовка** (не с его собственным списком колонок);
- один INSERT по-прежнему писать во временный файл и вливать в итоговый только после успеха этого INSERT: провал второго INSERT не должен портить/удалять CSV, уже полученный от первого;
- конкурентный доступ: два `.sql` в одной папке в одну таблицу — сериализация по ключу склейки.

**Не делать:** менять парсер SQL, обход дерева, формат ячейки, `converted.txt`.

**Проверка:** юнит-тесты (фикстуры в репозитории, не в `C:\Source\db`):

1. два INSERT в `t` в одном файле → один `t.csv`, одна строка заголовка, обе группы строк данных;
2. два `.sql` в одной папке оба пишут в `t` → один CSV;
3. `Alpha/t` и `Beta/t` → два разных `t.csv`;
4. заранее лежащий `t.csv` не затирается; склейка этого запуска идёт в `t(1).csv`;
5. второй INSERT с большим числом значений, чем колонок заголовка → этот INSERT пропущен, первый CSV на месте;
6. в файле нет второй строки `"id","item"` посередине.

## Что не трогать

- формат ячейки (кавычки, UTF-8 без BOM, `NULL` → `""`);
- пропуски `INSERT ... SELECT` / `SET` / без колонок;
- `C:\Source\db\converted.txt` (по-прежнему верхние папки с ≥1 успешным INSERT/CSV);
- запрет перезаписи **чужих** CSV, оставшихся с прошлого запуска.
