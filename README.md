# 2csv

Консольный конвертер: после запуска спрашивает `combo` или `db` и рекурсивно обходит выбранный корень, пишет CSV **рядом с исходным файлом**.

- `db` — `C:\Source\db`
- `combo` — `C:\Source\combo`

В выбранном корне:

- `.sql` — `INSERT ... VALUES` с PII в таблице или минимум в двух колонках, либо табличный дамп (первая непустая строка — шапка `,` / `;` / таб, не SQL) → CSV рядом;
- `.xlsx` / `.xls` — каждый лист книги → отдельный CSV (шапка = первая строка листа). Если в книге **больше 5 листов**, файл целиком пропускается, CSV от него нет;
- `.csv` / `.txt` — файлы с более чем 1 000 000 строк данных режутся на части не больше 500 000 строк.

`.xlsm`, `.xlsb`, `.ods` не трогаются. Правила — в [CONSTRAINTS_AND_POLICY.md](CONSTRAINTS_AND_POLICY.md).

PII-матчер регистронезависимый, многоязычный и поддерживает составные имена с `_`, `-`, `.`, пробелом и без разделителя. Технические колонки вроде `user_id` / `uuid` сами по себе зачёт не дают; документные идентификаторы (`national_id`, `passport_id`) остаются PII. Excel этим фильтром не ограничивается.

Нужен [Go](https://go.dev/dl/) не ниже версии из `go.mod`; при необходимости Go автоматически загрузит указанный toolchain. На новой машине достаточно один раз запустить `setup.ps1` — см. блок ниже.

## Новое устройство

Один раз в каталоге проекта. Политику выполнения меняем **только для текущего процесса**, не для всей машины:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\setup.ps1
```

Скрипт проверит Go (если нет — поставит через winget, иначе официальный MSI), выполнит `go mod download` и соберёт `2csv.exe`. Повторный запуск безопасен: уже установленный Go не ломается. `C:\Source\db` и `C:\Source\combo` скрипт не трогает.

## Сборка

В каталоге проекта, из обычной консоли (IDE не нужна):

```bat
go build -o 2csv.exe .
```

Появится `2csv.exe` в этой же папке.

## Запуск

В **PowerShell** текущая папка не ищется сама — пишите с `.\`:

```powershell
.\2csv.exe
.\2csv.exe --help
```

В cmd.exe можно и без точки:

```bat
2csv.exe
```

После запуска (кроме `--help`) программа печатает `combo/db:` и читает одну строку. Флага пути нет.

## Что появится в выбранном корне

- рядом с `.sql` — для INSERT: `{таблица}.csv` (все подходящие INSERT одной таблицы в этой папке за запуск объединяются в один файл, а заголовок берётся из первого успешно разобранного INSERT по порядку исходных файлов); для табличного дампа: `{имя_файла}.csv` (пример `GameSalad.sql` → `GameSalad.csv`), PII-фильтр проверяет имя файла и заголовок, а в журнал один раз записывается предупреждение, что это не INSERT;
- рядом с `.xlsx` / `.xls` — `{книга}_{лист}.csv` на каждый непустой лист (заголовок = первая строка листа); книга с более чем 5 листами не даёт ни одного CSV;
- при первом создании целевого CSV в запуске прежний файл с тем же точным именем заменяется; варианты `(n)` не создаются;
- `{корень}\_convert_done_.txt` — верхние папки, где конвертация `.sql` или Excel создала CSV;
- `{корень}\_convert_passed_.txt` — верхние папки, где конвертация завершилась без результата;
- `{корень}\_splitter_done_.txt` — верхние папки, где был нарезан хотя бы один `.csv` или `.txt`;
- `{корень}\_splitter_passed_.txt` — верхние папки, где подходящих для нарезки файлов не оказалось;
- `{корень}\_log.txt` — накопительный журнал запусков без обновляемой строки прогресса.

Конвертация и нарезка учитываются отдельно. Если имя папки уже записано в `_convert_*`, программа больше не конвертирует её файлы; если имя есть в `_splitter_*`, программа больше не выполняет нарезку. Папка полностью пропускается только тогда, когда её имя есть в списках обоих этапов. Чтобы повторить один этап, удалите имя папки из соответствующего списка. Файлы непосредственно в корне обрабатываются при каждом запуске и в списки не записываются.

Один пул воркеров на весь запуск: INSERT разбираются параллельно, запись в один CSV идёт сверху вниз.

CSV с более чем 1_000_000 строк данных режется на части не больше 500_000. Имена: `{имя}.csv`, `{имя}_2.csv`, `{имя}_3.csv`; заголовок повторяется в каждой части. `.txt` режется построчно без заголовка с сохранением расширения: `{имя}.txt`, `{имя}_2.txt`, `{имя}_3.txt`. Так же режутся уже лежавшие `.csv` и `.txt` в незавершённой для нарезки папке и в корне. Служебные файлы программы не режутся. Варианты `(n)` не создаются.

Одновременно обрабатывать один корень двумя экземплярами нельзя: второй запуск завершится с ошибкой, а системная блокировка автоматически освободится при закрытии первого процесса.

`.sql`, `.xlsx` и `.xls` удаляются только после того, как все CSV полностью записаны и состояние верхней папки сохранено. Удаление разрешено, если файл дал хотя бы один CSV и был обработан без ошибок. Файл без CSV или с ошибкой остаётся. При нарезке исходный `.csv` или `.txt` безопасно заменяется готовыми частями.

В консоли видны приглашение `combo/db:`, обновляемая раз в секунду строка `папка в обработке: <имя> (<N> с)`, итоги папок и ошибки отдельных файлов. Если список активных папок не помещается в 79 колонок, показывается папка, которая обрабатывается дольше остальных. Тот же вывод, кроме строки прогресса, дописывается в `_log.txt`. Итоги папок, уже отмеченных в одном из списков состояния, выводятся только в журнал.

Ручные SQL-фикстуры PII — `testfiles/10_pii.sql`, `11_no_pii.sql`, `12_mixed_pii.sql`, `13_one_column_rejected.sql`, `14_two_columns_ok.sql`, `15_technical_id_ignored.sql`, `16_document_id_counts.sql`. Табличные `.sql` — `testfiles/17_table_csv.sql`, `18_table_tsv.sql`, `19_table_no_pii.sql`. Ручные фикстуры Excel (не дампы из `C:\Source\db` / `C:\Source\combo`) — в `testfiles/09_excel/`. Пересоздать Excel: `go run ./testfiles/09_excel`.

## Коды выхода

| Код | Когда                                                                        |
| --- | ---------------------------------------------------------------------------- |
| 0   | обработка завершена без ошибок                                                |
| 1   | корень недоступен, уже обрабатывается другим процессом или программа не может настроить вывод |
| 2   | ошибка в аргументах командной строки или неверный / пустой ответ на `combo/db` |
| 3   | обход завершён, но один или несколько файлов завершились с ошибкой             |
