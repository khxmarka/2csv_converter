# sql2csv

Консольный конвертер: рекурсивно обходит `C:\Source\db`, из файлов `.sql` извлекает `INSERT ... VALUES` и пишет CSV **рядом с исходным SQL**. Правила разбора и формата — в [CONSTRAINTS_AND_POLICY.md](CONSTRAINTS_AND_POLICY.md).

Нужен [Go](https://go.dev/dl/) (проверялось на 1.26). На новой машине достаточно один раз запустить `setup.ps1` — см. блок ниже.

## Новое устройство

Один раз в каталоге проекта. Политику выполнения меняем **только для текущего процесса**, не для всей машины:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\setup.ps1
```

Скрипт проверит Go (если нет — поставит через winget, иначе официальный MSI), выполнит `go mod download` и соберёт `sql2csv.exe`. Повторный запуск безопасен: уже установленный Go не ломается. `C:\Source\db` скрипт не трогает.

## Сборка

В каталоге проекта, из обычной консоли (IDE не нужна):

```bat
go build -o sql2csv.exe .
```

Появится `sql2csv.exe` в этой же папке.

## Запуск

В **PowerShell** текущая папка не ищется сама — пишите с `.\`:

```powershell
.\sql2csv.exe
.\sql2csv.exe --help
```

В cmd.exe можно и без точки:

```bat
sql2csv.exe
```

Корень задан жёстко: `C:\Source\db`. Флага пути нет.

## Что появится в `C:\Source\db`

- рядом с `.sql` — `{таблица}.csv`: все успешные INSERT в одну таблицу в этой папке за запуск попадают в один файл, заголовок только от верхнего INSERT; `{таблица}(1).csv` появляется, только если такое имя уже было занято **до** запуска;
- `C:\Source\db\converted.txt` — имена **верхних** папок, в которых был хотя бы один успешный CSV (одно имя на строку). Если успехов не было, файл пустой.

Исходные `.sql` не меняются. Старые CSV не удаляются.

Сводка в консоль не пишется. Видно только: какая верхняя папка в обработке (одна строка, пока папка не закончится), когда папка полностью завершена, и критические ошибки.

## Коды выхода


| Код | Когда                                                            |
| --- | ---------------------------------------------------------------- |
| 0   | корень существует и обработан (даже если часть INSERT пропущена) |
| 1   | нет `C:\Source\db` или это не директория                         |
| 2   | ошибка в аргументах командной строки                             |
