# 2csv

Консольный конвертер: после запуска спрашивает `combo` или `db` и рекурсивно обходит выбранный корень, пишет CSV **рядом с исходным файлом**.

- `db` — `C:\Source\db`
- `combo` — `C:\Source\combo`

В выбранном корне:

- `.sql` — `INSERT ... VALUES` с PII в таблице или минимум в двух колонках, либо табличный дамп (первая непустая строка — шапка `,` / `;` / таб, не SQL) → CSV рядом;
- `.xlsx` / `.xls` — каждый лист книги → отдельный CSV (шапка = первая строка листа). Если в книге **больше 5 листов**, файл целиком пропускается, CSV от него нет.

`.xlsm`, `.xlsb`, `.ods` не трогаются. Правила — в [CONSTRAINTS_AND_POLICY.md](CONSTRAINTS_AND_POLICY.md).

PII-матчер регистронезависимый, многоязычный и поддерживает составные имена с `_`, `-`, `.`, пробелом и без разделителя. Технические колонки вроде `user_id` / `uuid` сами по себе зачёт не дают; документные идентификаторы (`national_id`, `passport_id`) остаются PII. Excel этим фильтром не ограничивается.

Нужен [Go](https://go.dev/dl/) (проверялось на 1.26). На новой машине достаточно один раз запустить `setup.ps1` — см. блок ниже.

## Новое устройство

Один раз в каталоге проекта. Политику выполнения меняем **только для текущего процесса**, не для всей машины:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\setup.ps1
```

Скрипт проверит Go (если нет — поставит через winget, иначе официальный MSI), выполнит `go mod download` и соберёт `2csv.exe`. Повторный запуск безопасен: уже установленный Go не ломается. `C:\Source\db` и `C:\Source\combo` скрипт не трогает.

## Сборка

В каталоге проекта, из обычной консоли (IDE не нужна):

```bat
go build -o 2csv.exe .
```

Появится `2csv.exe` в этой же папке.

## Запуск

В **PowerShell** текущая папка не ищется сама — пишите с `.\`:

```powershell
.\2csv.exe
.\2csv.exe --help
```

В cmd.exe можно и без точки:

```bat
2csv.exe
```

После запуска (кроме `--help`) программа печатает `combo/db:` и читает одну строку. Флага пути нет.

## Что появится в выбранном корне

- рядом с `.sql` — для INSERT: `{таблица}.csv` (все прошедшие PII-фильтр INSERT одной таблицы в этой папке за запуск в один файл, заголовок только от верхнего успешного INSERT); для табличного дампа: `{имя_файла}.csv` (пример `GameSalad.sql` → `GameSalad.csv`), тот же PII по stem и шапке, один `warn` что это не INSERT;
- рядом с `.xlsx` / `.xls` — `{книга}_{лист}.csv` на каждый непустой лист (заголовок = первая строка листа); книга с более чем 5 листами не даёт ни одного CSV;
- при первом создании целевого CSV в запуске прежний файл с тем же точным именем заменяется; варианты `(n)` не создаются;
- `{корень}\converted.txt` — накопительный список **верхних** папок, для которых **в этом запуске создан хотя бы один CSV** (конвертация или нарезка уже лежавшего файла). Пустая папка и папка с нулём полученных CSV в список не входят. Папки из списка при следующих запусках не обходятся.

Файлы `.sql`, `.xlsx` и `.xls` прямо в корне обрабатываются при каждом запуске и в `converted.txt` не попадают. Чтобы повторно обработать завершённые папки, удалите `converted.txt` вручную.

Один пул воркеров на весь запуск: INSERT разбираются параллельно, запись в один CSV идёт сверху вниз.

CSV с более чем 1_000_000 строк данных режется на части не больше 500_000. Имена: `{имя}.csv`, `{имя}_2.csv`, `{имя}_3.csv`. Так же режутся уже лежавшие `.csv` в ещё не завершённой папке и в корне. `converted.txt` не режется. Варианты `(n)` не создаются.

Одновременно обрабатывать один корень двумя экземплярами нельзя: второй запуск завершится с ошибкой, а системная блокировка автоматически освободится при закрытии первого процесса.

`.sql`, `.xlsx` и `.xls` удаляются после обработки, если из файла в этом запуске получен хотя бы один CSV. Файл без CSV остаётся. Другие `.csv` не удаляются.

Сводка в консоль не пишется. Видно: приглашение `combo/db:`; висящая строка `папка в обработке: <имя> (<N> с)` раз в секунду (несколько активных папок перечисляются вместе, у каждой свои секунды); итог папки (`папка <имя>: нет файлов` / `папка обработана: <имя>` / ошибка с причиной, если 0 CSV); `warn` табличного `.sql`; ошибка единицы с путём, таблицей и причиной (уже записанный CSV не откатывается). Пропуск книги с >5 листами отдельной строкой файла не пишется.

Ручные SQL-фикстуры PII — `testfiles/10_pii.sql`, `11_no_pii.sql`, `12_mixed_pii.sql`, `13_one_column_rejected.sql`, `14_two_columns_ok.sql`, `15_technical_id_ignored.sql`, `16_document_id_counts.sql`. Табличные `.sql` — `testfiles/17_table_csv.sql`, `18_table_tsv.sql`, `19_table_no_pii.sql`. Ручные фикстуры Excel (не дампы из `C:\Source\db` / `C:\Source\combo`) — в `testfiles/09_excel/`. Пересоздать Excel: `go run ./testfiles/09_excel`.

## Коды выхода


| Код | Когда                                                                        |
| --- | ---------------------------------------------------------------------------- |
| 0   | выбранный корень существует и обработан (даже если часть файлов/INSERT/книг пропущена) |
| 1   | нет выбранного корня или это не директория                                   |
| 2   | ошибка в аргументах командной строки или неверный / пустой ответ на `combo/db` |
