# 2csv

Консольный конвертер: после запуска спрашивает `combo` или `db` и рекурсивно обходит выбранный корень, пишет CSV **рядом с исходным файлом**.

- `db` — `C:\Source\db`
- `combo` — `C:\Source\combo`

В выбранном корне:

- `.sql` — извлекает `INSERT ... VALUES`, только если имя таблицы совпало со словарём персональных данных (PII) либо среди колонок есть минимум две различные зачётные PII-колонки;
- `.xlsx` / `.xls` — каждый лист книги → отдельный CSV (шапка = первая строка листа). Если в книге **больше 5 листов**, файл целиком пропускается, CSV от него нет.

`.xlsm`, `.xlsb`, `.ods` не трогаются. Правила — в [CONSTRAINTS_AND_POLICY.md](CONSTRAINTS_AND_POLICY.md).

PII-матчер регистронезависимый, многоязычный и поддерживает составные имена с `_`, `-`, `.`, пробелом и без разделителя. Технические колонки вроде `user_id` / `uuid` сами по себе зачёт не дают; документные идентификаторы (`national_id`, `passport_id`) остаются PII. Excel этим фильтром не ограничивается.

Нужен [Go](https://go.dev/dl/) (проверялось на 1.26). На новой машине достаточно один раз запустить `setup.ps1` — см. блок ниже.

## Новое устройство

Один раз в каталоге проекта. Политику выполнения меняем **только для текущего процесса**, не для всей машины:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\setup.ps1
```

Скрипт проверит Go (если нет — поставит через winget, иначе официальный MSI), выполнит `go mod download` и соберёт `2csv.exe`. Повторный запуск безопасен: уже установленный Go не ломается. `C:\Source\db` и `C:\Source\combo` скрипт не трогает.

## Сборка

В каталоге проекта, из обычной консоли (IDE не нужна):

```bat
go build -o 2csv.exe .
```

Появится `2csv.exe` в этой же папке.

## Запуск

В **PowerShell** текущая папка не ищется сама — пишите с `.\`:

```powershell
.\2csv.exe
.\2csv.exe --help
```

В cmd.exe можно и без точки:

```bat
2csv.exe
```

После запуска (кроме `--help`) программа печатает `combo/db:` и читает одну строку. Флага пути нет.

## Что появится в выбранном корне

- рядом с `.sql` — `{таблица}.csv`: все прошедшие PII-фильтр INSERT одной таблицы в этой папке за запуск попадают в один файл, заголовок только от верхнего успешного INSERT;
- рядом с `.xlsx` / `.xls` — `{книга}_{лист}.csv` на каждый непустой лист (заголовок = первая строка листа); книга с более чем 5 листами не даёт ни одного CSV;
- при первом создании целевого CSV в запуске прежний файл с тем же точным именем заменяется; варианты `(n)` не создаются;
- `{корень}\converted.txt` — накопительный список полностью обработанных **верхних** папок, по одному имени на строку. Папки из списка при следующих запусках не обходятся, даже если в них не было создано CSV.

Файлы `.sql`, `.xlsx` и `.xls` прямо в корне обрабатываются при каждом запуске и в `converted.txt` не попадают. Чтобы повторно обработать завершённые папки, удалите `converted.txt` вручную.

Одновременно обрабатывать один корень двумя экземплярами нельзя: второй запуск завершится с ошибкой, а системная блокировка автоматически освободится при закрытии первого процесса.

Исходные `.sql`, `.xlsx` и `.xls` не меняются. Другие CSV не удаляются.

Сводка в консоль не пишется. Видно только: приглашение `combo/db:`, какая верхняя папка в обработке (одна строка, пока папка не закончится), когда папка полностью завершена, и критические ошибки. Пропуск книги с >5 листами в лог не пишется.

Ручные SQL-фикстуры PII — `testfiles/10_pii.sql`, `11_no_pii.sql`, `12_mixed_pii.sql`, `13_one_column_rejected.sql`, `14_two_columns_ok.sql`, `15_technical_id_ignored.sql`, `16_document_id_counts.sql`. Ручные фикстуры Excel (не дампы из `C:\Source\db` / `C:\Source\combo`) — в `testfiles/09_excel/`. Пересоздать Excel: `go run ./testfiles/09_excel`.

## Коды выхода


| Код | Когда                                                                        |
| --- | ---------------------------------------------------------------------------- |
| 0   | выбранный корень существует и обработан (даже если часть файлов/INSERT/книг пропущена) |
| 1   | нет выбранного корня или это не директория                                   |
| 2   | ошибка в аргументах командной строки или неверный / пустой ответ на `combo/db` |
