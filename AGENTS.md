# 2csv — руководство для агентов

## Назначение проекта

`2csv` — консольная программа на Go для Windows. Она рекурсивно обрабатывает выбранный корень `C:\Source\db` или `C:\Source\combo`: преобразует SQL-дампы и листы Excel `.xlsx` / `.xls` в CSV рядом с исходниками, а затем нарезает большие `.csv` и `.txt` на части.

Основной рабочий поток: `cli -> app -> scan -> convert/xlsconv -> csvout -> удаление успешных исходников -> списки состояний и лог`.

## Контекст кодовой базы Graft

- Перед поиском по коду используйте Graft: `graft map`, `graft ask`, `graft callers`, `graft skeleton` или `graft grep`.
- Если локального графа нет или `graft check` сообщает об устаревании, выполните `graft build --lsp .`. Обычная сборка графа локальна и не требует LLM.
- Не запускайте `graft build --deep` без явного разрешения пользователя: этот режим обращается к внешней модели и расходует токены.
- `graft callers` может не учитывать косвенные и неоднозначные вызовы. Перед выводом о неиспользуемом коде выполните `graft grep "<symbol>" --fixed`, затем подтвердите результат через `rg` или `gopls`.
- Graft используется для навигации и оценки области влияния. Источниками истины остаются исходный код, `gopls`, тесты и подтверждённые проектные контракты.
- Каталог `graft/` является локальным регенерируемым кэшем и не добавляется в Git.

## Критичные контракты

- Конвертация и нарезка имеют независимые состояния: `_convert_done_.txt`, `_convert_passed_.txt`, `_splitter_done_.txt` и `_splitter_passed_.txt`.
- Папка из соответствующего `*_done_` или `*_passed_` повторно не проходит этот этап. Для ручного повтора имя папки удаляют из списка этапа.
- `_log.txt` накапливает вывод запусков, кроме обновляемой строки прогресса.
- Файлы непосредственно в корне не записываются в списки состояний и обрабатываются при каждом запуске.
- Существующий целевой файл может быть заменён, а успешный `.sql`, `.xlsx` или `.xls` — удалён. Любые изменения публикации, отката, удаления исходников и очистки временных файлов относятся к риску потери данных и требуют отдельных регрессионных тестов.
- Частичные ошибки отражаются в логе и счётчиках и завершают процесс с кодом `3`; код `0` означает, что обработка завершилась без ошибок.
- Фильтрация PII, правила имён CSV, ширина строк, порядок INSERT, лимиты записей и схема нарезки являются бизнес-контрактами.
- `.xlsx` читается потоково по строкам; `.xls` может загружать книгу целиком. Изменения параллельности и работы с памятью должны подтверждаться профилями и бенчмарками.
- Сохраняйте ограничения: не более пяти листов в книге, ограничение логической CSV-записи 64 MiB и существующие пределы SQL/табличных записей.

## Проверки

Выбирайте проверки по области риска. Базовый набор:

```bash
gofmt -l .
go test -count=1 ./...
go test -race -shuffle=on ./...
go vet ./...
GOOS=windows GOARCH=amd64 go vet ./...
golangci-lint run ./...
govulncheck ./...
go mod verify
GOOS=windows GOARCH=amd64 go build -trimpath -o /tmp/2csv.exe .
```

- `gofmt -l .` должен завершаться без вывода.
- После изменений конкурентности обязателен race detector.
- После изменений парсеров недоверенных данных запускайте целевые тесты и существующие fuzz-тесты.
- Изменения производительности проверяйте повторными `-benchmem`-замерами и `benchstat` на одной версии Go и одном оборудовании.
- Не запускайте `setup.ps1` без явной задачи: он может устанавливать Go, загружать модули и создавать бинарник в рабочем дереве.
